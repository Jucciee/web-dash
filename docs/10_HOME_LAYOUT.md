# 홈 배치

홈 상단의 **배치 편집** 아이콘 또는 **설정 → 배치 편집**에서 구성한다. 링크·API 애드온·호스트·Docker를 같은 섹션에 넣을 수 있다. 설치된 Immich 애드온도 일반 애드온과 같은 방식으로 배치한다.

## 사용 방법

1. **섹션 추가**에서 이름과 너비를 정한다. 예: 사진, 미디어, 개발, 서버.
2. 섹션의 **+** 버튼으로 다른 섹션의 링크와 위젯을 선택해 옮긴다. 항목 위의 손잡이를 다른 섹션으로 끌어도 된다.
3. 항목 손잡이를 끌어 가로·세로 위치를 바꾼다. 오른쪽 아래 모서리를 당기면 너비와 높이가 바뀐다.
4. 섹션 손잡이를 끌어 홈의 원하는 가로·세로 위치에 놓는다. 빈 공간에도 놓을 수 있다. 섹션 상단의 대각선 크기 버튼으로 너비와 최소 높이를 조절한다.
5. 톱니 버튼에서 소속 섹션·위치·크기를 숫자로 지정한다. **작게·기본·크게**도 선택할 수 있다.
6. **배치 저장**을 누른다. 저장 전에는 홈에 반영되지 않는다. **변경 취소**, **되돌리기·다시 실행**, 드래그 중 **Esc**를 사용할 수 있다.

항목과 섹션의 이동 손잡이에서 방향키는 이동, Shift + 방향키는 크기 조절이다. 크기 버튼에서는 방향키로 너비·높이를 조절한다. 좁은 화면의 섹션 손잡이는 표시 순서를 바꾼다. 섹션 톱니 설정의 **섹션 가로 위치·세로 위치**로 좌표를 직접 지정할 수도 있다. 마우스와 터치 손잡이는 같은 배치 모델을 사용한다.

## 표시와 유지

- 홈과 각 섹션 내부는 각각 12열이다. 항목의 12칸 너비는 그 섹션 전체이며, 섹션의 12칸 너비는 홈 전체다. 한 높이 칸은 48px이며 칸 사이 간격은 12px다. 섹션 제목은 한 칸을 사용한다.
- 겹치는 항목과 섹션은 아래로 밀린다. 다른 열과 의도적으로 비운 공간은 유지된다. 항목을 키워 섹션 높이가 늘어날 때도 다른 섹션이 겹치지 않도록 이동한다. 작은 위젯은 내용 영역에서 스크롤할 수 있다.
- 작은 링크 카드는 이름을 먼저 표시하고, 부가설명은 최대 두 줄과 남는 공간 안에서 표시한다. 짧은 타일은 아이콘을 숨겨 이름 공간을 확보한다. 이름과 설명의 전체 문구는 마우스를 올려 확인할 수 있다.
- 화면이 좁으면 섹션과 항목을 한 열로 정돈하고 내용 높이에 맞춘다. 넓은 화면의 좌표와 크기는 유지된다. 모바일에서는 톱니 설정으로 세부 크기를 지정할 수 있다.
- 기존 사용자는 **자동 배치**로 시작한다. 저장 후 사용자 지정 배치가 된다. 편집 화면에서 **자동 배치 → 배치 저장**으로 원래 자동 배치를 복원할 수 있다.
- 새 링크나 활성화한 애드온은 사용자 지정 배치에서도 **새 항목** 섹션에 자동으로 나타난다. 다시 편집해 원하는 섹션으로 옮긴다. 이미 배치한 링크를 숨기거나 애드온을 비활성화하면 자리는 보존되고, 다시 활성화했을 때 같은 자리를 사용한다.
- 삭제한 링크·애드온 참조는 표시하지 않는다. 섹션을 삭제할 때는 그 안의 항목을 지정한 다른 섹션으로 옮기며 실제 링크·애드온은 삭제하지 않는다.
- 섹션은 처음에 접어둘 수 있다. 접힌 섹션 안의 위젯은 펼칠 때까지 조회하지 않는다. 검색은 섹션 이름과 링크·위젯 이름, 링크 주소·설명을 함께 찾는다.
- 배치 편집과 화면 설정 미리보기에서는 호스트·Docker·애드온의 실제 API를 조회하지 않는다. 실제 값은 홈이나 해당 상태 페이지에서 확인한다.

홈 사용자 CSS는 `.home-layout`, `.home-layout-section`, `.home-layout-item`, 기존 `.service-card`, `.host-widget`, `.docker-widget`, `.addon-widget`을 대상으로 적용할 수 있다. 배치 편집은 별도 경로여서 홈 CSS가 화면을 숨겨도 접근할 수 있다.

## 저장 계약

`settings.homeLayout`을 `20261010_home_layout` migration으로 추가한 SQLite JSON 컬럼에 저장한다. 기존 링크 그룹·애드온 정의·개인 인증값은 별도로 유지하며 배치는 종류와 ID만 참조한다. 브라우저의 로컬 저장소에 의존하지 않는다.

```json
{
  "version": 1,
  "mode": "custom",
  "sections": [{
    "id": "a6e0bf3d-8f29-46ee-aafb-2fa1a65d37b1",
    "name": "서버",
    "x": 0,
    "y": 2,
    "width": 12,
    "minRows": 0,
    "collapsed": false,
    "items": [{ "kind": "host", "refId": "", "x": 0, "y": 0, "width": 6, "height": 7 }]
  }]
}
```

`kind`는 `link`, `addon`, `host`, `docker`다. 링크·애드온의 `refId`는 UUID, 호스트·Docker는 빈 문자열이다. 한 항목은 한 번만 배치한다. 좌표는 0부터 시작한다. 섹션의 `x`·`y`는 홈 안의 위치, 항목의 `x`·`y`는 소속 섹션 안의 위치다. 섹션은 최대 60개, 전체 항목은 최대 500개, 섹션 너비는 3~12, 최소 높이는 0~48, 항목 너비는 1~12, 높이는 1~24다. 항목은 12열·4096행, 섹션은 12열·65536행을 벗어나지 않아야 한다. 섹션 높이는 내부 항목의 가장 아래 행 또는 최소 높이 중 큰 값에 제목 한 칸을 더한 값이다. 빈 섹션은 항목 추가 영역으로 최소 세 칸을 확보한다.

이전 배치에는 섹션 좌표가 없어도 된다. 좌표를 생략한 섹션은 남는 공간에 배치하며 다음 저장 때 좌표가 함께 저장된다. `x`와 `y` 중 하나만 지정하거나 섹션이 겹치면 서버가 저장을 거절한다. 기존 JSON 컬럼을 사용하므로 이 확장에 별도의 DB migration은 필요하지 않다.

자동 배치는 `{"version":1,"mode":"auto","sections":[]}`다. `PATCH /api/v1/settings`에 `homeLayout`만 보낼 수 있으며 세션·CSRF·`If-Match` revision을 검사한다. 충돌 시 기존 배치를 덮어쓰지 않고 최신 배치를 명시적으로 불러올 수 있다. 섹션·항목 값의 범위, ID·종류, 중복과 겹침을 서버에서도 검사한다. 설정 요청 한도는 배치와 사용자 CSS를 함께 저장할 수 있도록 256KiB다.

계약은 [OpenAPI](openapi.json)의 `HomeLayout`, `HomeSection`, `HomeItem`을 참고한다. 호스트 위젯은 현재 web-dash가 수집하는 호스트를 표시한다. 다른 서버의 API 값은 별도 애드온으로 연결할 수 있다.

## 검증

`npm --prefix web run test:layout`은 항목·섹션의 겹침 처리, 빈 공간 이동, 이전 배치 호환, 다른 섹션으로 이동, 모바일 순서, 추가/삭제/비활성화한 항목, 반복 이동과 크기 변경을 검사한다. 브라우저 테스트는 실제 API에 저장한 좌표, 포인터 드래그·크기 변경, 키보드, 되돌리기·취소, 충돌, 새 항목, 검색, 미리보기, 모바일을 확인한다. 긴 설명과 큰 글자·아이콘을 사용한 링크는 카드·타일·목록의 1~3칸 높이에서 이름이 잘리지 않는지도 검사한다. Go 테스트는 저장·재시작·migration 보존·검증 실패 시 rollback을 확인한다.
