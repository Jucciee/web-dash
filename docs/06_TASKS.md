# 개발 작업 목록

이 목록은 실제 구현 순서다. 체크 항목은 담당자를 정해 끝까지 완료하고, 다음 단계에서 필요한 계약을 먼저 합의한다.

## 단계 1: 저장되는 카드 하나

- [x] Go 모듈에 Gin·GORM·gormlite·gormigrate를 연결하고 React·TypeScript·Vite 프로젝트를 만든다.
- [x] README에 로컬 실행 명령과 지원 버전을 기록한다.
- [x] SQLite migration을 적용한다.
- [x] SCS·gormstore·gorilla/csrf로 초기 관리자 생성, 로그인, 세션, CSRF를 구현한다.
- [x] 기본 대시보드·그룹 생성, 카드 CRUD를 연결한다.
- [x] 반응형 그룹·카드 화면과 카드 편집 dialog를 만든다.
- [x] 현재 구현한 API 계약을 OpenAPI로 옮기고 DTO 타입을 맞춘다. 후속 API는 각 단계에서 추가한다.

완료 확인: 로그인하고 카드 한 개를 추가·수정한 뒤 서버를 재시작해도 구성값이 남는다. 인증되지 않은 변경은 거절된다.

## 단계 2: Nginx 가져오기

- [x] 업로드·붙여넣기·시작 파일 선택 UI를 만든다.
- [x] 크기·파일 수·가상 경로 검사를 구현한다.
- [x] nginx-go-crossplane의 파싱 결과와 가상 Open·Glob을 연결하고 줄 번호를 보존한다.
- [x] server_name·listen·정적 location·proxy_pass에서 후보를 만든다.
- [x] 불확실한 주소·미제공 include를 안내한다. 전체 Nginx 실행 검증은 후속 단계다.
- [x] 후보 선택·이름·주소·그룹 수정 UI를 만든다.
- [x] preview session과 commit 트랜잭션을 연결한다.
- [ ] `nginx -T` 출력의 파일 구분도 지원한다.

완료 확인: 서버 세 개가 들어 있는 설정에서 두 개만 선택해 등록할 수 있다. 잘못된 URL은 등록 전에 안내된다. 서버 실제 경로를 참조한 include는 읽히지 않는다.

## 단계 3: Caddy 가져오기와 재가져오기

- [x] 공식 Caddy lexer로 정적인 사이트·upstream·단순 snippet·최상위 가상 파일 import를 추출한다.
- [x] 원본 내용을 보관하지 않는 30분 미리보기와 선택 등록을 구현한다.

- [ ] 격리된 Caddy adapt worker의 입력·출력 계약을 구현한다.
- [ ] 제한된 작업 환경과 timeout·출력 제한을 적용한다.
- [ ] 중첩된 route·host·path·reverse_proxy에서 후보를 추출한다.
- [ ] import 파일 누락·환경값 의존·커스텀 모듈 오류를 안내한다.
- [ ] 후보의 sourceKey와 원본 snapshot을 저장한다.
- [ ] 재가져오기의 신규·변경·동일·사라짐·모호함을 표시한다.
- [x] 중복 commit을 막고 재전송 결과를 일관되게 반환한다.

완료 확인: 가져온 카드 이름을 바꾼 뒤 다시 가져와도 이름과 그룹이 유지된다. 원본 URL 변경은 확인 후 적용되며 원본에서 사라진 카드가 자동 삭제되지 않는다.

## 단계 4: Docker 읽기 전용 상태

- [x] Compose 폴더 검색과 running 컨테이너의 실제 공개 TCP 포트 가져오기를 구현한다.
- [x] SDK 요청 hook으로 ping과 목록 조회 외 Docker API 요청을 차단한다.

- [x] 내부 network에 Docker socket proxy overlay를 구성한다. 실제 Docker 기동은 설치 환경에서 확인한다.
- [x] 공식 SDK wrapper와 transport 경로·메서드 제한을 구현한다.
- [x] Docker 연결 환경 안내와 새로고침 UI를 만든다.
- [x] 목록·실행 상태·health·CPU·RAM·누적 네트워크를 DTO로 변환한다.
- [x] 화면을 보고 있는 동안 주기적으로 조회하고 5초 공유 캐시로 요청을 합친다.
- [ ] 카드에 연결할 컨테이너 selector를 저장한다.
- [ ] 컨테이너 교체·여러 후보·연결 끊김을 표시한다.
- [x] Docker 응답에서 환경변수와 불필요한 정보를 제외한다.

완료 확인: 컨테이너가 멈췄을 때와 Docker 연결이 끊겼을 때를 구분한다. 프록시와 Go transport 양쪽에서 변경 요청이 거절되는 것을 확인한다.

## 단계 5: 웹 응답·호스트 지표

- [x] 링크별 웹 상태 확인 사용 여부를 저장한다.
- [x] 사설 주소 허용, DNS·redirect 검사, timeout·본문 제한을 적용한다.
- [x] 인증이 필요한 응답과 네트워크 실패를 구분한다.
- [x] 페이지 접속 시 웹 응답을 한 번 확인하고 홈·관리 카드에 표시한다. 수동 확인과 마지막 확인 정보도 제공한다. 사람이 접속하지 않거나 페이지를 계속 열어두면 주기적인 검사를 하지 않는다.
- [x] 서버 내 gopsutil로 실행 호스트 또는 Linux 호스트 마운트의 CPU·RAM·디스크·가동 시간을 읽는다.
- [ ] 별도 원격 호스트 수집기를 연결한다.
- [ ] 수집기 token 발급·폐기와 지표 전송을 구현한다.
- [x] 마지막 확인 시각·오래된 정보·미연결·실제 수집 환경을 표시한다.
- [ ] 짧은 기간의 호스트 추세와 보관 정책을 적용한다.

완료 확인: 수집기 없는 설치에서 컨테이너 값을 호스트 지표로 표시하지 않는다. 호스트의 값과 도구로 확인한 값의 측정 기준이 일치하는지 확인한다.

## 파서 테스트 자료

| 자료 | 확인할 결과 |
| --- | --- |
| Nginx HTTP server 1개 | 도메인·포트 후보 생성 |
| Nginx HTTP redirect + HTTPS | 동일 서비스 후보 비교, HTTPS 주소 확인 |
| Nginx 다중 server_name | alias 중 대표 주소를 선택 가능 |
| Nginx wildcard·regex·변수 | 주소 없는 후보 제외·이유 안내 |
| Nginx include·upstream | 제공된 파일만 해석, 대상 정보 보존 |
| Nginx quote·주석·중첩 | 문법 구조와 줄 번호 유지 |
| Caddy 명시적 주소·reverse_proxy | 공개 주소와 내부 대상 구분 |
| Caddy snippet·import | 업로드 묶음 안에서 변환 |
| Caddy nested route·path matcher | 조건을 유지하고 불확실한 URL 경고 |
| Caddy 미설치 모듈·환경값 | 해결 가능한 오류 안내 |
| 공통 순환·절대 경로·대량 파일 | 실제 호스트 파일 접근 없이 제한 |
| 재가져오기·중복commit | 사용자 수정 보존, 한 번만 적용 |

## 첫 배포판 이후 검토할 작업

- 읽기 전용 마운트 폴더에서 직접 가져오기.
- 설정 변경 감지 후 자동 재분석과 적용 미리보기.
- 여러 Docker 호스트와 인증된 원격 연결.
- 여러 대시보드와 사용자별 배치.
- 호스트 지표 보관 기간과 추세 화면 확장.
- 앱별 API 애드온 사전 설정 모음, 여러 요청과 토큰 갱신이 필요한 연결 방식.

Docker·프록시 제어는 이 계획의 후속 작업에도 포함하지 않는다. 현재 목표인 설정 가져오기, 대시보드 편집, 상태 확인의 완성도를 먼저 높인다.
