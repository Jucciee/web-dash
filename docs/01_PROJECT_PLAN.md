# 프로젝트 계획서

작성일: 2026-10-03

## 1. 제품 목표

홈서버 사용자가 서비스 주소를 하나씩 찾아 입력하는 수고를 줄이고, 브라우저에서 자신의 대시보드를 구성하게 한다. Nginx·Caddy 설정에서 서비스 후보를 발견하고, 사용자가 확인해 카드로 등록한다. 등록된 카드는 Docker 상태 및 웹 응답 상태와 연결할 수 있다.

첫 시연의 핵심 장면은 **설정 파일 가져오기 → 서비스 후보 확인 → 선택 등록 → 대시보드 완성**이다.

## 2. 기능 범위

| 기능 | 첫 버전의 동작 | 완료 기준 |
| --- | --- | --- |
| 초기 설정·로그인 | 관리자 계정 하나 생성, 세션 로그인 | 초기 설정 완료 후 다시 계정을 만들 수 없음 |
| 서비스 카드 | 이름, URL, 아이콘, 설명, 그룹 편집 | 추가·수정·숨김·삭제가 새로고침 후 유지됨 |
| 그룹·배치 | 그룹 편집, 카드 순서 변경 | 마우스와 키보드로 순서 변경 가능 |
| Nginx 가져오기 | 업로드·붙여넣기, 여러 파일, 후보 추출 | 도메인·프로토콜·포트·단순 경로를 미리보기에서 수정 가능 |
| Caddy 가져오기 | Caddyfile과 관련 파일 가져오기 | 사이트 주소와 프록시 대상을 후보로 표시 |
| 후보 선택 등록 | 일괄 선택, 개별 수정, 중복 확인 | 선택한 항목만 한 번에 저장됨 |
| 재가져오기 | 기존 서비스와 신규·변경 후보 비교 | 기존 이름·아이콘·그룹·순서를 덮어쓰지 않음 |
| Docker 연결 | 연결 검사, 컨테이너 목록·상태·health·사용량 | Docker 데몬으로 변경 요청이 나가지 않음 |
| 상태 연결 | 카드와 컨테이너 연결·해제 | 컨테이너 교체와 연결 끊김을 표시함 |
| 웹 상태 | 사용자가 켠 대상의 HTTP 확인 | 로그인 필요·연결 실패·미확인을 구분함 |
| 호스트 지표 | 별도 Go 수집기로 CPU·RAM·디스크 조회 | 실제 호스트 지표인지 데이터 출처를 표시함 |
| 백업·복원 | 카드·그룹·표시 설정을 내보내고 복원 | 복원 전 변경 미리보기, 트랜잭션 적용 |

현재 범위에서 Docker 시작·중지·재시작·생성·삭제·exec와 프록시 설정 수정·reload를 지원하지 않는다. 이 기능을 위한 API나 UI도 만들지 않는다.

첫 기능 시연(MVP)은 카드 편집, 두 종류 설정 가져오기, Docker 상태까지다. 호스트 지표와 백업·복원은 첫 배포판(v1) 완료 조건에 포함한다.

## 3. 주요 사용자 흐름

### 처음 실행

1. 설치 시 발급한 초기 설정 토큰으로 관리자 계정을 만든다.
2. 대시보드에 직접 카드 추가 또는 설정 가져오기를 선택한다.
3. Docker 연결은 선택 사항으로 안내하고, 연결 검사를 제공한다.
4. 필요한 경우 호스트 수집기를 연결한다.
5. 실제 데이터가 없는 화면에는 다음 행동을 설명한다.

### 설정 가져오기

1. Nginx 또는 Caddy를 선택한다. 자동 감지는 보조 기능으로 둔다.
2. 텍스트를 붙여넣거나 설정 파일을 올린다. 여러 파일이면 시작 파일을 선택한다.
3. 파일을 분석하고, 발견 항목과 필요한 관련 파일·지원하지 못한 문법을 보여준다.
4. 후보마다 서비스 이름, 사용자 접속 URL, 그룹, 선택적 Docker 연결을 확인한다.
5. 이미 등록된 후보는 기존 항목 연결 또는 새 항목 추가를 선택한다.
6. 선택 항목을 한 트랜잭션으로 등록한다.

`proxy_pass http://photos:3000` 또는 `reverse_proxy photos:3000`은 내부 연결 대상이다. 카드의 기본 URL은 사용자가 접속할 공개 도메인·경로에서 만든다. 내부 주소를 접속 주소로 자동 확정하지 않는다.

### 재가져오기

변경 비교는 신규, 변경, 동일, 원본에서 사라짐으로 표시한다. 변경을 사용자가 적용하기 전까지 대시보드는 유지한다. 원본에서 사라진 항목도 자동 삭제하지 않고 카드 유지·연결 해제·카드 삭제 중 하나를 고르게 한다. 출처가 모호한 항목은 수동 연결을 제안한다.

## 4. 쉬운 사용을 위한 기준

- 서버 기술 용어는 필요한 부분에 설명을 붙인다. 예: `healthcheck 없음`은 오류가 아니라 `건강 상태 정보 없음`으로 표시한다.
- 카드 하나에 컨테이너 실행 상태와 웹 응답 상태를 각각 표시한다.
- 데이터 수집이 끊기면 마지막 값과 마지막 확인 시간을 남기고 `오래된 정보`를 표시한다.
- 가져오기 경고에 파일 이름·줄 번호·해결 방법을 제공한다. 원본 설정은 편집하지 않는다.
- 처음에는 카드 정렬과 그룹 이동만 제공하고, 자유로운 크기 조절은 후속 작업으로 둔다.
- 드래그 외에 `위로 이동`, `아래로 이동`, `그룹 변경`을 제공한다.
- 연결 오류에서 주소 오류·권한 부족·응답 시간 초과를 구분한다.
- 모바일에서는 한 열 배치와 큰 조작 영역을 제공한다.

## 5. 지원 문법과 한계

| 종류 | 기본 지원 | 사용자 확인이 필요한 경우 |
| --- | --- | --- |
| Nginx | `http`·`server`·`location` 블록, 명시적 `server_name`, `listen`, 정적인 `proxy_pass`, 관련 `include` | 와일드카드·정규식 이름, 변수 URL, 복잡한 rewrite, TCP `stream`, 경로 정규식 |
| Caddy | 명시적 사이트 주소, 기본 HTTP/HTTPS 주소, 정적인 `reverse_proxy`, 업로드 묶음 내 `import` | 런타임 placeholder, 커스텀 모듈, 환경값 의존, 복잡한 matcher·경로 변경 |

Nginx 서버 이름은 와일드카드와 정규식도 허용하므로 이 값을 그대로 클릭 가능한 URL로 만들 수 없다. 단순 경로도 rewrite 규칙이 있으면 접속 주소를 확인해야 한다. [서버 이름 문서](https://nginx.org/en/docs/http/server_names.html), [프록시 문서](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)

사용자가 기존 서버에서 얻은 `nginx -T` 출력도 가져오기 대상으로 지원한다. 이 명령은 설정 검사와 파일 참조 확인도 수행하므로, 대시보드가 업로드 내용을 대상으로 실행하는 방식으로 구현하지 않는다. [명령어 문서](https://nginx.org/en/docs/switches.html)

## 6. 일정 제안

3~4명이 주 단위로 작업을 나누는 8주 계획이다. 인원별 역할은 고정하지 말고 각 작업을 끝까지 담당하도록 한다.

| 기간 | 산출물 |
| --- | --- |
| 1주 | UI 흐름, API 계약, 프로젝트 초기 구조, 관리자 초기 설정 |
| 2주 | 카드·그룹 CRUD, 저장, 기본 반응형 대시보드 |
| 3주 | Nginx 파서, 업로드, 가져오기 미리보기 |
| 4주 | Caddy 어댑터, 선택 등록, 중복·재가져오기 비교 |
| 5주 | Docker 읽기 전용 연결, 상태·health·사용량, 카드 연결 |
| 6주 | 웹 상태 확인, 호스트 수집기, 오래된 정보 처리 |
| 7주 | 배치 편집, 백업·복원, 모바일·키보드 사용 |
| 8주 | Compose 설치, 실제 환경 검증, 처음 사용하는 사람의 사용성 점검 |

## 7. 최종 완료 조건

새 설치에서 관리자가 웹 UI만으로 파일을 가져오고, 카드 10개를 골라 등록하고, 이름·그룹·순서를 변경할 수 있다. Docker 연결 후 상태가 표시되며 연결을 끊어도 서비스 카드 편집은 계속 가능하다. 앱 재시작 후 저장된 구성이 유지되고, 백업으로 다른 설치에 복원할 수 있다.

Docker 변경 요청이 나가지 않는지, 설정 원본이 바뀌지 않는지, 가져오기 중 서버의 임의 파일을 읽지 않는지를 검증한다. 호스트 수집기가 없으면 호스트 지표를 `미연결`로 표시한다.
